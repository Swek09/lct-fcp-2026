# Технические проверки в GitHub Actions

Workflow: [.github/workflows/ci.yml](../.github/workflows/ci.yml).
Проверки запускаются для каждого push, pull request и ручного запуска.
Автодеплой выполняется для актуального коммита `main` только после успешных
backend и frontend jobs.

| Этап | Команда / проверка | Что покрывает |
| --- | --- | --- |
| Backend | `go test ./... -race -count=1` | Unit-тесты и интеграция с настоящими PostgreSQL 17.6 и Redis 8.2.1; обнаружение гонок Go |
| Анализ Go | `go vet ./...` | Статические проверки типичных ошибок Go |
| Протокол деплоя | `python3 -m unittest discover -s ../infra/deploy -p 'test_*.py' -v` | 8 проверок архивов образов, SHA и запрета подмены образов других сервисов |
| Frontend | `npm ci`, `npm run build` | Установка по lock-файлу, TypeScript и сборка Vite |
| Контейнеры | Docker build API и web; Compose `fsp-ci` с `--wait` | Старт с миграциями, PostgreSQL, Redis и Mailpit в изолированной среде |
| До деплоя | `/api/health`, `/release.json` в `fsp-ci` | Здоровье сервиса и точное совпадение SHA коммита |
| После деплоя | Те же запросы по публичному HTTPS | Доступность `fsp.swek.tech` и актуальность релиза |

Go unit-тесты покрывают 162 семейства заданий, варианты и оценивание,
порог 9/12, старые попытки, числовые ответы и приватность ключей;
парсер потребности и ранжирование; валидацию резюме; PDF с кириллицей и
несколькими страницами; 24 случая Origin; SMTP через TCP и требование STARTTLS;
безопасное преобразование аватаров и валидацию контактов компании.

Интеграция содержит 13 сценариев: роли и контакты, аватары и расширенные кабинеты,
раскрытие и отзыв доступа к новым контактам, содержательное резюме
и видимость, CSRF, приглашения и зарплата, короткие задания и права на решения,
регистрация и одноразовая верификация почты, тесты и интервалы повторов,
вакансии/отклики/избранное/отзыв согласия, серверный дедлайн, PDF и сброс пароля
с отзывом сессий, OpenAPI без ответов, сохранение грейда при потере Redis-сессии.
Конкурентные отклики и решения не создают дублей и не обходят интервалы.

Это не браузерное E2E: автоматических UI-тестов, визуальной регрессии,
нагрузочных тестов и проверки экспертной точности грейда в workflow пока нет.
Браузер, PDF-отрисовка и эксперименты качества проверяются отдельно;
результаты и ограничения записаны в [validation.md](validation.md).

Деплой использует ограниченный SSH endpoint, резервную копию БД,
проверку здоровья и откат образов при ошибке. Это механизмы эксплуатации,
а не дополнительные автоматические тесты. Секреты и изоляция сервера
описаны в [deployment.md](deployment.md).
